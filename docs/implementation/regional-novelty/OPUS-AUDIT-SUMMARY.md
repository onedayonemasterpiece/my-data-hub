**Главные находки**

1. **Живого master у MDH никогда не было.** За 3 месяца и 817 коммитов база в Kaggle ни разу не заработала с данными. Сегодня `/healthz` отвечает `master_absent`. Из 266 блогеров импортировано 0. План пишет про master «сохранить», будто он работает. Первым шагом должен быть живой цикл: запуск → восстановление из Dataset → чтение через MCP → сохранение → остановка → повторный запуск.
2. **Будут две системы сохранения.** У MDH уже есть своя checkpoint-машинерия: около 7,4 тыс. строк, плюс 8,5 тыс. строк кода приёмки. Вживую она не проверена. План добавляет поверх неё перенос из РКБ и не решает, что делать со старой.
3. **Журнал на Dev защищает от потери, которой у MDH нет.** Опыт РКБ: эта машинерия занимает около 8,9 тыс. строк, и в октябре блокировки шли именно из неё (переполнение spool, нехватка памяти при сохранении, журнал около 80 МБ в каждой версии Dataset). Собственный аудит РКБ пришёл к выводу, что журнал дублирует Postgres. У MDH источники публичные: при потере notebook посты просто перечитываются с последнего сохранённого курсора. Достаточно схемы «`pg_dump` → версия Dataset перед остановкой, восстановление при старте». Это та формулировка, которую сам владелец дал для РКБ.
4. **Отдельные notebook для исполнителей и протокол их замены не нужны.** Владелец в своих решениях прямо разрешил вариант «всё в одном notebook». Один цикл: восстановить → собрать посты → оценить → сохранить → остановиться. Кончилась бесплатная квота — необработанное остаётся в базе, следующий цикл стартует в свежем окружении. Это и есть решение владельца «остановить и запустить свежий».
5. **Перестраховки на стабильных инструментах.**
   - Очередь стадий внутри notebook — это просто SQL-запрос плюс ограничение уникальности в Postgres. Слой orchestration здесь не нужен.
   - «Актуальный OpenCode» — это одна строка установки при старте notebook и запись версии в лог. Release feed, продвижение версий и SHA-пины бинарника не нужны.
   - Работы под объём 100 ГБ отложить: пилот наберёт мегабайты в сутки. Нужна одна метрика размера базы в логе цикла.
6. **Общий пакет `kaggle-runtime` (320 строк)** не подключён ни к одному потребителю. `rotation.py` и `releases.py` написаны заново, это не перенос работающего кода. SHA-пины кода аудит РКБ уже удалял как лишние. Предлагаю порядок: сначала продукт в MDH, потом выносить в пакет то, что реально понадобится второму потребителю. Живой код РКБ ради пилота MDH не трогать.

**Нужно решение владельца — два вопроса:**

1. Согласен ли он не переносить в MDH журнал на Dev? Цена такого решения — при потере notebook повторяется один цикл сбора.

Сколько постов проходит до отказа и возвращается ли доступность в новом окружении — главная неизвестная продукта. Отдельный риск: провайдер может счесть смену окружения ради новой квоты обходом лимитов и закрыть маршрут.
